# `test/`: how the contract is proven correct

`forge test` runs every suite below except three: the fork tests, which need `ROBINHOOD_RPC_URL` and are skipped
without it, and the two checks that run outside Foundry, the upgrades plugin's layout check (`upgrade/layout/check.py`)
and the coverage gate (`coverage/check.py`).

## The suites

| Suite | Path | What it proves |
|---|---|---|
| Unit | `unit/` | The libraries without a proxy. `LeverageMath`: the constants, `floorDiv`, the lines and the cap line, the payout multiple, the payout, the max profit and `touched` (`LeverageMath.t.sol`); the time, liquidation, sale, open-gate and withdrawal checks (`LeverageMathChecks.t.sol`); the fees, the settle, sale and repayment splits, and the design's two worked examples (`LeverageMathSplits.t.sol`); the leverage as an input, from 1x to 10,000x (`LeverageMathLeverage.t.sol`); the shared harness is in `LeverageMathShared.sol`. Then `ConfigLib`, `OrderLib` and `BreakerLib`; the storage layout (`FlashOptionStorage.t.sol`: every slot and byte offset); the ABI (`IManicFlashOptionAbi.t.sol`: every selector, event topic and error selector); and the mock token (`MockUSDG.t.sol`: it behaves like the real USDG) |
| Behaviour | `concrete/<function>/` | One folder per function with ordered checks: a `.tree` file (every branch, in the contract's check order) and the tests made from it, which bulloak holds to the tree in CI. Each revert test breaks its own check and every later one, so its error also proves the order. `pay/` and `checkSignature/` reach internal functions through the harness. Six folders cover rules that cross functions and have no tree: `views/` (the hash helpers, and every getter against raw storage), `reentrancy/` (every state-changing function entered again from inside a token transfer, and every getter read from inside one, which must refuse), `brakes/` (what the halt, a pause and a tripped breaker stop, ARCHITECTURE §8.10), `breaker/` (what each ending counts in the payout circuit breaker, its window and trip, and the attack it stops, §8.11), `counters/` (the books' 32-bit counters refuse to wrap) and `leverages/` (BTC at 1000x, 500x and 100x on one pool: each leverage is a market of its own, and each bet opens, sells, is liquidated and settles at its own) |
| Fuzz | `fuzz/` | Properties over random inputs, one suite per function or library: the maths properties and money conservation (`LeverageMathFuzz`, `LeverageMathMoneyFuzz`); every way a signature can be wrong (`OrderFuzz` and `SignatureFuzz`: another domain, a malleable `s`, a bad `v` or length, random bytes, ERC-1271 wallets, EIP-7702 accounts); the order rules, an order used late, early or twice (`OrderRulesFuzz`); rounding at tiny stakes and open→sell loops (`RoundingFuzz`, security checklist MATH-3). The contract-level properties run on a market at any leverage (`Base_Test._leverageFor`, `_priceNear`), and a batch holding another market's bet must be refused |
| Invariant | `invariant/` | Stateful tests on BTC at 1000x, 500x and 100x, sharing one pool. `handlers/` drive random sequences of 20 actions: `MarketHandler` (the price and the clock), `TradingHandler` (open, a burst of opens, sell), `SettlementHandler` (liquidate, settle, a batch mixing markets that must be refused, refund, repay, and the wind-down), `PoolHandler` (fund, withdraw, claim, sweep, a donation) and `AdminHandler` (the brakes, the market's settings, the breaker, freezes, a stranger). All build on `BaseHandler`: the call counters, and the checks around every call (the money, the statuses, the breaker). `stores/FlashOptionStore.sol` keeps the ghost state. `Invariant.t.sol` checks the 14 invariants of docs/ARCHITECTURE.md §12 after every call, in two campaigns: `Leverage_Invariant_Test` (the launch pool) and `SmallPool_Invariant_Test` (a $20 pool whose winners become IOUs). After every run, `afterInvariant` winds the pool down and must find nothing stuck; `test_EveryActionDoesItsWork` proves each action does its work |
| Access | `access/` | Who may call what. `AccessMatrix.t.sol`: the role map as a table of 32 rows (the 30 functions that change state, pausing and halting apart), each called by the 11 users from the same state; the allowed succeed and the rest are refused with the exact error; the table is held to the compiled ABI, and a random address is refused everywhere. `KeyBlastRadius.t.sol`: what each key can do alone if it leaks, each bound pinned. `FakePriceLoop.t.sol`: the fake-price loop with one stolen relayer key, across three leverages, and a revoked key that can't restart it |
| Scenarios | `scenarios/` | Worked scenarios with hand-checkable amounts, each ending run through the settlement checkers and checked to the base unit. `LiquidateScenarios`, `SettleScenarios`, `SellScenarios` and `RepayScenarios`: the base bet ($10 for a minute on BTC, θ 3 bp, floor 1.3x, cap 4x, at $83,884) liquidated, settled and sold at quoted valuations, and a queue of four IOUs on a pool seeded with $20, repaid in order. `FlashOptionScenarios` and `LeverageTradingScenarios`, with their shared set-up in `FlashOptionShared.sol`: BTC at 500x and 100x beside 1000x on one pool; the checks that depend on the leverage; opens at every bound and the widest line each leverage allows; liquidations, settlements and sales with their fees; bets of three leverages expiring in one second; the exposure gate reading the shared pool; and IOUs of three leverages in one queue, repaid in order |
| Signing | `signing/Eip712Vectors.t.sol` | Replays `fixtures/eip712_vectors.json`, the EIP-712 vectors shared with the backend: deployed at the vectors' address on their chain, the contract gives the same domain, digests and signatures, and accepts every signature. The vectors are made with Foundry's `cast`, never with this repo's Solidity |
| Upgrade | `upgrade/` | `Upgrade.t.sol` upgrades a proxy holding real state (IOUs, claimable payouts, open bets at 1000x, 500x and 100x, changed settings and roles) to `mocks/ManicFlashOptionV2Mock`, which appends a field and sets it with an upgrader-only `reinitializer(2)`: the upgrade must change only the implementation slot, the initializer version and the new field, every view must read the same, and V2 must carry on with V1's bets. `layout/check.py` runs OpenZeppelin's upgrades plugin on the code against its base, every deployed version and 15 variant patches of `src/`, each a rule of ARCHITECTURE §5 kept or broken ([`layout/README.md`](upgrade/layout/README.md)) |
| Fork | `fork/` | Runs against Robinhood Chain mainnet. `Fork_Base_Test` runs the whole set-up and the checkers on the real USDG, acting as its freeze and pause role holder. `RealUsdg.t.sol`: the contract with the real token (signer types, a frozen winner, a pause, a cancelled authorization, every payment out, a transfer's gas). `MockUsdgVsReal.t.sol`: the mock and the real token take the same steps and must end the same. `.github/workflows/fork.yml` runs it once a week, on a pull request that changes the contract, the mock, the test bases or the fork tests, and on demand |
| Gas | `gas/` | `Gas.t.sol` measures each call the backend makes, from cold state and in the worst case, into `snapshots/ManicFlashOption.json`. `check.py` compares the numbers with the base branch (a call more than 5% dearer fails, unless the pull request carries the label `gas-regression-accepted`) and makes docs/gas.md's tables. `.github/workflows/gas.yml` also fails when a fresh run doesn't match the committed snapshots |
| Script | `script/` | The deploy scripts. `Sequence.t.sol` runs the whole sequence through each script's own `run()`, with chains.toml's anvil table: the mock token, the deployment, the markets and the pool (twice: nothing changes), a bet opened and settled as the backend makes it, an upgrade, and the record. `Deploy.t.sol`, `Configure.t.sol` and `Upgrade.t.sol` show each script's check fails on each value it guards. `Inputs.t.sol`: the deployed market settings are the tested ones, and the chains the scripts accept. The scripts are deployed from the build (`vm.deployCode`), since each holds the contract's bytecode |
| Coverage gate | `coverage/check.py` | Reads `forge coverage`'s report: every line, function and branch of `src/` must be covered, apart from the branches it lists as unreachable, each with its reason (audit/static-analysis.md). A listed branch that a test does reach fails too, so the list can't go stale |

## The shared set-up

| Path | What it holds |
|---|---|
| `Toolchain.t.sol` | Proves the pinned toolchain works (cancun target, OpenZeppelin imports, transient guard) |
| `Base.t.sol` | The base of every test that runs the contract behind its proxy: the users, the mock USDG, the implementation, a proxy initialized with `Defaults` in the transaction that deploys it, and the BTC market, created and switched on. Helpers build, sign and open an order (`_order`, `_terms`, `_signOrder`, `_stakeAuth`, `_open`), pick a leverage and a price for the fuzz suites (`_leverageFor`, `_priceNear`), and move to a small pool with the exposure gate off (`_useSmallPool`, for IOUs) |
| `SettlementBase.t.sol` | The base of the tests of every ending, `liquidate`, `settle`, `sell`, `repay` and the safety refund, `refundExpired`: a pool with $1,500 of free money, helpers that open bets (`_bet`, `_betWith`) and sign sale orders (`_sellOrder`, `_sellTerms`, `_signSell`), and the five checkers, `_expectLiquidated`, `_expectSettled`, `_expectSold`, `_expectRefunded` and `_expectRepaid`. Each walks the ending with its own model of the books and of the payout circuit breaker (from `Calculations`, never `LeverageMath`), runs it, then checks every log, every pool field, every breaker field, every slot of every id, the repay queue and every balance |
| `utils/` | `Defaults` (every test setting), `Users` (the named accounts), `LayoutReader` (reads every stored field straight from its slot), `LayoutWriter` (writes a state no function can reach: a market's open gate switched off, for the tests of the IOU path), `UsdgSigner` (USDG permit and EIP-3009 signatures), `Examples` (the worked examples' constants: the $83,884 entry price, a $10 stake, 1 bp, the $500 floor and the launch config), `Calculations` (independent reference formulas that never call `src/`, among them the settle, sale and repayment splits and the liquidation fee), `OrderSigner` (signs order digests as the backend does, and builds the malleable twin of a signature) and `LeverageConfigs` (settings for other leverages: the launch config fitted to any leverage, the 500x and 100x tier settings, and each BTC market's planned settings) |
| `mocks/` | Test doubles: `MockUSDG` (copies Paxos USDG, including its silent no-op on a reused EIP-3009 nonce), `MockERC1271Wallet`, `MockDecimalsToken` (any decimals, for `initialize`'s check), `ManicFlashOptionV2Mock` (a second implementation for the upgrade tests), and four tokens that misbehave: `MockFeeOnTransferToken` (delivers less than sent), `MockFalseToken` (returns false), `MockGasBurnerToken` (runs out of gas, in itself or one call deeper) and `MockReentrantToken` (calls back in from a transfer, a `receiveWithAuthorization` pull included); `MockOddERC1271Wallet` answers `isValidSignature` wrongly in four ways; `DrainerImplementationMock` is what a leaked upgrader key could install |
| `harnesses/` | Thin contracts that expose internal functions as external calls, so tests can call them and check their reverts: `LeverageMathHarness`, `ConfigLibHarness`, `OrderLibHarness` and `BreakerLibHarness` (the libraries; the last holds one `Breaker` in storage), and `ManicFlashOptionHarness` (the contract plus `exposed_pay` and `exposed_checkSignature`, deployed behind a proxy like the real one) |
| `fixtures/` | Inputs shared with the backend or the scripts, with how each was made (`README.md`): `eip712_vectors.json` and its generator, `eip712_vectors.py`; and `scripts/chains-bad-enabled.toml`, a chains file the deploy scripts must refuse |

## Naming

Test contracts are `<Function>_<Kind>_Test`. Test functions are `test_<Behaviour>`, `test_RevertWhen_<Condition>`,
`testFuzz_<Property>` and `invariant_<NN>_<Property>`. Details in [`docs/CONVENTIONS.md`](../docs/CONVENTIONS.md) §9.

## Running

Run everything with `forge test`. CI uses `FOUNDRY_PROFILE=ci`, which runs more fuzz and invariant cases: 10,000 per
fuzz property, against 1,000 locally. The deep run, `FOUNDRY_PROFILE=deep forge test --match-path 'test/fuzz/*'`, runs
100,000 per property; `.github/workflows/deep-fuzz.yml` runs it once a week if `dev` changed that week, and on demand.
Every run draws new inputs. A failure prints the inputs that broke it and a line `Fuzz seed: 0x… (use --fuzz-seed to
reproduce)`: rerun that test with `--fuzz-seed 0x…` to replay it exactly.

An invariant campaign is `runs` runs of 100 calls, with every invariant checked after every call: 32 runs locally, 128
in CI, and 1,000 in the deep run, `FOUNDRY_PROFILE=deep forge test --match-path 'test/invariant/*'`, which the same
weekly workflow runs. A failure prints the call sequence that broke it, shrunk. Foundry also keeps it in
`cache/invariant/failures/` and replays it first on the next run; delete that folder to start afresh.

The fork tests run when `ROBINHOOD_RPC_URL` is set; the public RPC, `https://rpc.mainnet.chain.robinhood.com`, is
enough.

The two checks outside Foundry:
- the upgrades plugin's layout check, with Node.js 22: `python3 test/upgrade/layout/check.py --base origin/dev` takes
  about a minute, and CI runs it on every pull request and push, comparing with the base;
- the coverage gate: `forge coverage` writes `lcov.info` (the exact command is in `.github/workflows/ci.yml`), then
  `python3 test/coverage/check.py lcov.info` checks it. CI runs both on every pull request and push.
